# KiNO!BERNIC

Версия KinoLab для портативных приставок Anbernic на muOS. Только онлайн-поток,
без торрентов.

Проверено на **Anbernic RG34XXSP**, muOS `2601.0_JACARANDA`, экран 720×480.
Раскладка рассчитана и на остальные экраны линейки: 640×480 (RG35XX, RG40XX,
RG28XX) и 720×720 (RG CubeXX).

## Как устроено

Компилятора на приставке нет и pygame тоже нет, зато есть Python 3.11 и SDL2
2.28 с ttf и image. Поэтому всё написано на Python поверх SDL2 через `ctypes` —
собирать нечего, файлы просто копируются на карту.

| Файл | Что делает |
|---|---|
| `app.py` | экраны, навигация, цикл событий |
| `sdl.py` | обвязка SDL2/SDL2_ttf/SDL2_image через ctypes |
| `layout.py` | метрики под разные экраны линейки |
| `gamepad.py` | evdev: кнопки и крестовина |
| `player.py` | запуск mpv и управление им по IPC |
| `resolve.py` | Veoveo: серии, озвучки, выбор видеопотока |
| `search.py` | поиск по названию |
| `catalog_sync.py` | сборка «Главной», подборок, обложек и баннеров на карту |
| `account.py`, `pair.py` | аккаунт KinoLab и привязка приставки |
| `update.py` | версия и проверка обновлений на GitHub |
| `control.py` | сокет управления для отладки |

## Установка

Скопировать `app/` в `MUOS/application/KiNO!BERNIC/` на карте приставки,
затем один раз собрать данные:

    python3 catalog_sync.py

Запускается из меню muOS: **Applications → KiNO!BERNIC**.

## Управление

Крестовина — навигация, **A** выбрать, **B** назад, **L1/R1** вкладки,
**Start** поиск, **L1+R1** убрать подсказки. В плеере: **A** пауза,
**←→** ±30 секунд, **Y** выбор озвучки, **B** выход с подтверждением.

Коды кнопок на muOS отличаются от документа `знания/KEY_MAPPING.md`,
написанного под стоковую прошивку: L1 = 308, R1 = 309, SELECT = 310,
START = 311. Сняты нажатиями, поправка дописана в конец того же документа.

## Что измерено на железе

Декод (клипы 30 fps, повторные прогоны на чистом устройстве):

| Материал | к реальному времени |
|---|---|
| H.264 720×480 @2 Мбит/с | 11.7× |
| H.264 1280×720 @4 Мбит/с | 5.2× |
| HEVC 720×480 @1.5 Мбит/с | 4.0× |
| HEVC 1280×720 @3 Мбит/с | 1.95× |

Живой поток Veoveo на экране: 710×576@50fps — ноль пропущенных кадров,
113% одного ядра из 400% доступных, буфер набегает на 90 секунд вперёд.

Приложение в покое ест 0.0% процессора: рисует по событию, между нажатиями
спит в `select`. Исключение — бегущая строка под выбранной карточкой, 5.1%.

## Грабли, на которые уже наступили

**Мастер-плейлист нельзя отдавать mpv напрямую.** ffmpeg 4.4 открывает все
аудиодорожки группы разом, часть валится с `Invalid data found`, и видео не
стартует вовсе — 36 секунд впустую при кэше 0.05 с. `resolve.py` разбирает
мастер сам и отдаёт плееру видеоплейлист и одну дорожку.

**Рунг выбирается по ширине, а не по высоте.** У широкоформатного кино
«1080p» — это 1920×800, и на экран 720×480 он ляжет как 720×300. Выбор по
высоте брал 1280×534 вместо 720×300: втрое больше трафика ради пикселей,
которые GPU тут же выбросит.

**Аудиодорожки перечислены для каждого рунга своей группой.** Без фильтра по
`GROUP-ID` выбранного варианта их выходит 39 вместо 13 — тринадцать штук трижды.

**`pkill -f "<шаблон>"` по SSH убивает сам себя**: шаблон попадает в командную
строку собственного `sh -c`. Сессия умирает раньше цели, а mpv остаётся жить и
портит следующие замеры — так родились цифры, завышенные в 2.4 раза. Только
`pkill -x mpv`.

**Из SSH звук не открывается**: `--ao=alsa` падает с `Playback open error:
Host is down`, потому что в сессии нет `XDG_RUNTIME_DIR`. Приложению,
запущенному из меню, muOS отдаёт окружение сам.

**Битмаска возможностей устройства ввода не говорит о раскладке.** Она
перечисляет коды, которые устройство умеет слать, но не какая кнопка какой
шлёт. Проверять надо нажатиями.
